# forecast-baseline

[![tests](https://github.com/basovdanil/forecast-baseline/actions/workflows/tests.yml/badge.svg)](https://github.com/basovdanil/forecast-baseline/actions/workflows/tests.yml)

**[English](README.en.md)** · [Русский](README.md)

Бэктест базовых прогнозов на одном временном ряду. Показывает, какой метод
действительно лучше на ваших данных, до того как тянуть ARIMA и бустинг.

Только стандартная библиотека Python 3.8+.

## Пайплайн

```text
sales.csv ──▶ скользящие окна ──▶ 5 методов ────────────▶ MAE / MAPE ──▶ work/metrics.json
date,value     min-train = 56      naive, mean, ma7,        по каждому    победитель
                                   seasonal7, trend        методу        + вывод в --json
```

## Методы

| Метод | Что прогнозирует |
| --- | --- |
| `naive` | повторяет последнее значение |
| `mean` | среднее по всей истории |
| `ma7` | среднее за последние 7 точек |
| `seasonal7` | значение той же точки прошлой недели |
| `trend` | линейный тренд по всей истории (МНК) |

Метрики: MAE в единицах ряда и MAPE в процентах. MAPE считается без точек с
нулевым фактом, иначе деление на ноль.

## Схема проверки

Скользящее начало прогноза: ряд режется на историю и следующие `horizon` точек,
история удлиняется на одну точку, прогноз повторяется. Каждое окно даёт ошибку по
каждому методу, в конце ошибки усредняются. Так исключается подгонка под будущее:
метод видит только прошлое.

```
python forecast.py backtest --input demo/sales.csv --horizon 7 --min-train 56
```

Ключи: `--horizon` (по умолчанию 7), `--min-train` (56), `--out metrics.json`,
`--csv metrics.csv`, `--json`.

## Демо

`demo/sales.csv` — 730 дней дневной выручки, синтетика: сид 42, тренд, выходные,
месячная волна и шум. Ряд пересоздаётся скриптом `demo/make_demo.py`.

Результат на горизонте 7 дней при 668 окнах:

| Метод | MAE | MAPE |
| --- | --- | --- |
| seasonal7 | 4 616,03 | 8,81 % |
| trend | 6 135,91 | 11,51 % |
| mean | 6 303,27 | 11,07 % |
| ma7 | 6 392,00 | 11,95 % |
| naive | 7 975,55 | 14,92 % |

Недельная сезонность бьёт тренд вдвое: в синтетике она есть по построению.
На ряде без сезонности порядок будет другим, поэтому метод выбирается прогоном,
а не по репутации.

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | готово |
| `2` | неверные аргументы |
| `3` | файла нет |
| `4` | ошибка данных: нет колонок `date`/`value`, не число, ряд короче окна |

## Тесты

```
python -m unittest discover -s tests
```

16 тестов: каждый метод на коротком ряду, циклический сдвиг недели, МНК на
идеальной прямой, MAE/MAPE с нулевыми фактами, число окон бэктеста, разбор чисел
с пробелами и десятичной запятой, коды возврата и запись `--out`/`--csv`.

## Данные

Ряд в `demo/` синтетический. Совпадения с реальной выручкой случайны.

## Границы

Методы одномерные, без промо, праздников и внешних факторов: если продажи
определяются акциями, базовая линия их не поймает. `seasonal7` жёстко зашит на
неделю, для месячной сезонности нужен свой лаг. Ряд без пропусков и дублей дат:
проверка календаря не делается, шаг считается равномерным.
